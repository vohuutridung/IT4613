# Source and reimplementation matrix

## Scope and evidence key

The active implementation is `mind_no_body_15field`: a deliberate 15-field variant. The pinned source uses 17 fields, including `cur_body` and `his_body`; this project does not claim to reproduce that full model or its reported competition result. The source checkout is `upstream-mind/` at `f632bdf7b1136dff142835f9fe69c8ce5f8c166d`, as recorded by `source_lock.json` and `source_manifest.json`. Neither file was edited in this review.

Report page references below are to Huige Cheng's *MIND News Recommendation — Technical Report* (the competition solution report), not the separate MIND dataset introduction paper. Source file line references are within the pinned checkout. “Verified in source” means the behavior is visible in that code or report; it does not imply a local numerical comparison.

`source_lock.json` and `source_manifest.json` remain immutable historical source-lock records. They do not certify current DB or checkpoint bytes. The active implementation state is described by the current config and this matrix; a future pipeline invocation hashes the exact DB it will open, checks it against the expected manifest, and independently checks SQL schema and mapping content. Physical paths are trace metadata only. The entries below describe code changes made in the current static review; they have not been runtime-verified.

## Historical state before the H1/H2/M1 correction

The earlier review snapshot found that training fingerprinted the default DB even when another `--db` was opened; dev masking applied 92% to candidate DIDs without filtering train-seen IDs; the membership builder considered only candidate rows; resume used `assert_existing_objects_matched()` alone and did not cross-check optimizer iteration, schedule and consumed-example cursor. These describe the code state before this correction. They are retained here as historical review context, not as claims about the code below or as changes to upstream provenance.

## Changes made in the current static review

- **H1 — DB identity:** training, inference, and membership construction pass the exact resolved `db_path` to identity validation and loaders. At pipeline invocation, actual DB bytes are hashed without a size-only cache, compared with the adjacent manifest's expected SHA/byte count, and SQL schema plus mapping content are checked. Installation paths remain trace-only; stable artifact keys are relative names. A final file-stat check rejects replacement/mutation between the content hash and SQLite schema/mapping reads. No DB hash or DB open was executed in this review.
- **H2 — dev mask:** added `dev_new_did_masked`. It masks only unseen candidate DIDs and keeps train-seen IDs. Membership is defined by raw train `behaviors.tsv` history plus impression candidates, mapped through the retained DID vocabulary; click labels and news metadata are not used. The existing candidate-only membership artifact cannot prove this set and is rejected by the new provenance check. Per-candidate-occurrence random draws are a disclosed choice because the report does not state the sampling unit.
- **M1 — resume:** model and Adam slots are built before strict restore; both `assert_existing_objects_matched()` and `assert_consumed()` are required. New checkpoint state stores update, optimizer iterations, examples-seen count, separate sampling-cursor ordinal, candidate key at the cursor, and schedule index. Resume validates the newest complete checkpoint shards, counter equality, next-schedule index, saved LR against the preceding schedule step (`rtol=1e-6`, `atol=1e-12`), the cursor count formula (including a short final batch), and deterministic replay through the saved candidate key. Fresh mode refuses an output directory that already contains checkpoint files. None of these paths was runtime-tested here.
- `source_lock.json` and `source_manifest.json` are historical immutable records, not current-artifact validation reports. They were not edited.
- **Iterator bug fixed:** the training iterator now requests and returns candidate metadata, validates empty-batch and array alignment contracts, and preserves the seeded impression order when assembling candidate rows. This metadata supplies the candidate key required for exact resume-prefix verification. The path had previously returned an undefined local `m`; this defect is corrected in code. No training iterator was executed in this review.
- **Execution-only performance preparation:** history arrays are decoded/materialized once per impression within each batch and loss scalars are read at effective-batch boundaries. Per-candidate metadata remains enabled for cursor provenance. These changes have not been runtime-parity checked or benchmarked; no speedup is claimed.

- Removed duplicate PAD/UNK, embedding width, attention width/activation, DIN hidden-width, artifact initialization seed, default candidate-batch, metric-cutoff, and checkpoint-cadence literals from active preprocessing/loader/encoder/artifact-builder/training paths; those values now come from the canonical config. Current values remain unchanged (`PAD=0`, `UNK=1`, embedding width 100, attention hidden 128/ReLU, DIN hidden 100/sigmoid, artifact seed 20261024, metric cutoffs 5/10, checkpoint every 25 updates).
- Removed the local extra mask that zeroed a type embedding for a non-padding entity with a PAD type ID. The pinned source adds entity/type embeddings directly and masks/pools by the entity sequence; this correction follows that visible operation. Whether the local type-PAD embedding matches the private source table is still unknown.
- Made Keras Adam's local non-source options explicit in the config: zero weight decay, AMSGrad off, no clipping, EMA off, JIT setting on. This documents the reimplementation; it does not resolve upstream `bert-adam`.
- Corrected an internal flag that said entity vectors were pretrained only when both entity and type matrices were present. Entity-ID and entity-type matrix availability are now tracked separately; this flag did not affect the forward path.
- Kept the existing safe behavior for source unknowns: no source optimizer, pooling, or RNG algorithm was substituted based on name or shape.

## Status classification

- **A — proven code defects corrected:** undefined training iterator return; DB compatibility fingerprint previously tied to a default/location instead of the DB actually opened; resume cursor previously lacked candidate-key proof. These are code fixes only, not runtime PASS claims.
- **B — deliberate and documented reimplementation differences:** active 15-field no-body profile; report-based `dev_new_did_masked` retains train-seen DIDs and masks only unseen candidate occurrences, while pinned executable validation code applies a different masking path. The membership source set (raw train history plus candidates) is supported by the pinned dictionary-generation code; the report does not establish whether its random draw is per DID or per occurrence, so occurrence-level draws are a local choice.
- **C — unresolved source behavior:** concrete `bert-adam` implementation, exact historical triangle scheduler and step convention, private pooling/DIN numerics and masks, historical RNG stream, and whether the local tokenizer/GloVe artifacts match the original author artifacts. No values were guessed to erase these differences.

These changes alter code/config fingerprints. No artifact manifest, source lock, DB, vocabulary, tokenizer, embedding, raw file, or checkpoint was changed. The stored DB remains readable under the unchanged PAD/UNK semantics; a future Stage 01 `--resume` must not treat its old code fingerprint as if it were generated by the edited source. A future model resume must revalidate the retained checkpoint against the new implementation rather than bypassing its fingerprint guard.
